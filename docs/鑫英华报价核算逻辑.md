# 鑫英华报价核算逻辑

> **系统**：nova2 铝合金画框切框算料报价系统  
> **版本**：V4  
> **更新日期**：2026-07-28  

---

## 一、核心概念

### 1.1 基本物理参数

| 参数 | 符号 | 值 | 说明 |
|------|------|-----|------|
| 单支原料总长 | 全长 | 3.15 m | 计价长度 |
| 单支原料可使用长度 | 可用长 | 3.05 m | 扣除端头损耗后的可切割长度 |
| 锯片损耗 | 切损 | 0.015 m | 每次切割的锯缝宽度 |
| 内径壁厚补偿 | 壁厚 | 0.005 m | 内径框额外增加的材料厚度 |

### 1.2 计费模式

| 模式 | 枚举值 | 适用场景 | 材料计算方式 |
|------|--------|---------|-------------|
| 批量单 | `BATCH` | 大批量相同规格 | 按整支料排料（3.05m） |
| 零散单 | `RETAIL` | 小批量 / 不同规格混合 | 按框周长 × 1.2 系数 |

### 1.3 尺寸类型

| 类型 | 含义 | 切割补偿 |
|------|------|---------|
| 外径 (OD) | 框体外侧尺寸 | 只加锯片损耗（0.015m） |
| 内径 (ID) | 框体内侧尺寸 | 加锯片损耗（0.015m） + 壁厚（0.005m） |

### 1.4 输入数据结构

每条算料项目包含：
- **型号**（model）：如 "G3406"
- **颜色**（color）：如 "哑黑"
- **尺寸**：宽 × 高（cm），尺寸类型（外径/内径）
- **数量**：该尺寸对应框的个数

    ↓

## 三、详细计算步骤

### 步骤 1：分组

按 `型号 + 颜色` 分组，同型号同颜色的所有尺寸汇总到一组内统一排料。

```
key = model + "-" + color
group[key] = [item1, item2, ...]
```

### 步骤 2：展开为待切边池

每组内，每个框的每条边展开为独立的"待切边"（CalculatedEdge）。

**边长计算**：

- **外径 (OD)**：
  - 宽度边 = 宽(cm)/100 + 0.015（锯片损耗）
  - 高度边 = 高(cm)/100 + 0.015

- **内径 (ID)**：
  - 宽度边 = 宽(cm)/100 + 0.015 + 0.005（壁厚补偿）
  - 高度边 = 高(cm)/100 + 0.015 + 0.005

每个框产生 **4 条边**（2 宽 + 2 高），乘以数量 N = 4N 条边。

```
例如：1 个 50×70 外径框
  → 宽边: 0.50 + 0.015 = 0.515m × 2 = 1.030m
  → 高边: 0.70 + 0.015 = 0.715m × 2 = 1.430m
  → 总需切割: 2.460m
```

### 步骤 3：排料算法

#### 3.1 FFD（First-Fit Decreasing，首次适应递减）

1. 所有边按长度**降序排序**
2. 取最长的边，放入第一支能容纳它的料
3. 如果所有料都装不下，开新料
4. 重复直到所有边装完

> 贪心策略，简单快速，但不一定全局最优。

#### 3.2 最优排料（DP 背包 + 最长边优先）

核心思路：**每支料找出"最优装入组合"**，使浪费最少。

1. 所有边按长度降序排序，取最长边作为当前支料基准（**必装**）
2. 剩余短边用 **0-1 背包 DP**，找出能装入剩余空间且总长最大的组合
3. 装完后移除已装边，开下一支料
4. 重复直到所有边装完

**DP 实现细节**：
- 边长离散化到毫米（×1000 取整）
- `dp[j]` = 容量 j 时的最大总装入长度
- 采用 `Int32Array` 和 `Uint8Array` 优化内存

#### 3.3 双算法选优 + 一致性校验

系统**同时运行 FFD 和最优算法**，并进行一致性校验：

1. 计算两种算法的 segments 总长度，与 allEdges 总长度对比（容差 0.0001m）
2. 校验通过 → 选支数（`barCount`）更少的算法
3. 支数相等 → 默认选 FFD（更稳定）
4. 校验失败 → 回退 FFD（防御性处理）

**最终结果**：
```
totalBars = plans.length   ← 该组所需整料支数
```

### 步骤 4：四级查价链路

确定**型材材料成本单价**（costMaterial，元/米）。

| 优先级 | 阶段 | 规则 | 标记 |
|--------|------|------|------|
| 1 | **精确匹配** | `型号 + 颜色` 完全匹配成本资料库中的记录 | `exact` |
| 2 | **颜色复用** | 查颜色复用规则表，如果源颜色匹配规则，使用目标颜色的单价 | `reuse` |
| 3 | **型号回退** | 仅按型号匹配（忽略颜色），取第一条匹配记录 | `model-fallback` |
| 4 | **估算** | 以上全失败 → `materialPrice × 0.6`（报价单价的 60%） | — |

**线密度取值**（用于重量计算）：
```typescript
actualWeightPerMeter = costRecord?.weightPerMeter ?? config.defaultWeightPerMeter
```

优先使用成本资料库记录中的线密度，回退到全局默认值。

### 步骤 5：双轨制计算

系统同时维护**两条成本轨道**：

| 轨道 | 用途 | 配件费率 | 切工费率 | 税率 |
|------|------|---------|---------|------|
| **报价轨道**（quote track）| 对外报给客户的价格 | `quoteAccessoryPrice` | `quoteCuttingFee` | `quoteTaxRate` |
| **成本轨道**（cost track）| 内部成本核算（真实底价） | `costAccessoryPrice` | `costCuttingFee` | `costTaxRate` |

---

#### 5A. 批量单模式 (BATCH)

**客户报价（报价轨道）**：

```
avgMeters = totalBars × 3.15 / totalQuantity       ← 单框平均耗材长度
perFrameCuttingCost = quoteCuttingFee               ← 单框切工费（固定）
unitPrice = [avgMeters × materialPrice + quoteAccessoryPrice + perFrameCuttingCost] × (1 + quoteTaxRate)
totalPrice = Σ(unitPrice × item.quantity)
```

**内部成本拆分（报价轨道）**：

```
materialCostGroup = totalBars × 3.15 × costMaterial
accessoryCostGroup = totalQuantity × quoteAccessoryPrice
cuttingCostGroup = totalQuantity × quoteCuttingFee
subTotalQuote = materialCostGroup + accessoryCostGroup + cuttingCostGroup
taxCostGroup = subTotalQuote × quoteTaxRate
totalCost = subTotalQuote + taxCostGroup
```

**成本轨道计算**（用于利润核算）：

```
costAccessoryCostGroup = totalQuantity × costAccessoryPrice
costCuttingCostGroup = totalQuantity × costCuttingFee
subTotalCost = materialCostGroup + costAccessoryCostGroup + costCuttingCostGroup
costTaxCostGroup = subTotalCost × costTaxRate
costGrandTotal = subTotalCost + costTaxCostGroup
```

---

#### 5B. 零散单模式 (RETAIL)

**注**：零散单不按整料排料，按每个框的实际周长 × 1.2 系数计算材料用量。

**客户报价（报价轨道）**：

```
perimeter = (宽 + 高) × 2 / 100          ← 周长（米）
retailCuttingLength = perimeter × 1.2    ← 零散切割所需材料长度
perFrameCuttingCost = quoteCuttingFee    ← 单框切工费（固定）
unitPrice = [retailCuttingLength × materialPrice + quoteAccessoryPrice + perFrameCuttingCost] × (1 + quoteTaxRate)
totalPrice = Σ(unitPrice × item.quantity)
```

**内部成本拆分（报价轨道）**：

```
materialCostGroup = Σ(retailCuttingLength × costMaterial × item.quantity)
accessoryCostGroup = Σ(quoteAccessoryPrice × item.quantity)
cuttingCostGroup = Σ(quoteCuttingFee × item.quantity)
subTotalQuote = materialCostGroup + accessoryCostGroup + cuttingCostGroup
taxCostGroup = subTotalQuote × quoteTaxRate
totalCost = subTotalQuote + taxCostGroup
```

**成本轨道计算**：

```
costAccessoryCostGroup = Σ(costAccessoryPrice × item.quantity)
costCuttingCostGroup = Σ(costCuttingFee × item.quantity)
subTotalCost = materialCostGroup + costAccessoryCostGroup + costCuttingCostGroup
costTaxCostGroup = subTotalCost × costTaxRate
costGrandTotal = subTotalCost + costTaxCostGroup
```

---

### 步骤 6：利润计算

```
毛利 = totalPrice - costGrandTotal
利润率 = (毛利 / totalPrice) × 100%
```

> 关键：利润 = **报价总额** - **真实成本总额**（成本轨道），不是报价轨道成本。

### 步骤 7：重量计算（可选）

仅在启用"显示重量"时执行：

```
materialWeight = totalBars × 3.15 × actualWeightPerMeter   ← 材料毛重
accessoryWeight = totalQuantity × defaultWeightPerAccessorySet  ← 配件总重
totalWeight = materialWeight + accessoryWeight               ← 成品总重
```

## 四、全局费率配置（PriceConfig）

### 4.1 费率字段总览

| 字段 | 类型 | 单位 | 轨道 | 说明 |
|------|------|------|------|------|
| `materialPrice` | number | 元/米 | — | 材料报价单价（统一基准） |
| `mode` | PricingMode | — | — | 批量单 / 零散单 |

#### 报价费率（对客户展示）

| 字段 | 单位 | 说明 |
|------|------|------|
| `quoteAccessoryPrice` | 元/套 | 每套配件费 |
| `quoteCuttingFee` | 元/个 | 每个框的切工费 |
| `quoteTaxRate` | % | 如 0.13 = 13% |

#### 成本费率（内部核算）

| 字段 | 单位 | 说明 |
|------|------|------|
| `costAccessoryPrice` | 元/套 | 内部配件成本 |
| `costCuttingFee` | 元/个 | 内部切工成本 |
| `costTaxRate` | % | 内部适用税率 |

### 4.2 每单费率覆盖（CostOverride）

管理员可在成本资料库设置**全局默认费率**，销售在算料时可对**当前报价单**临时覆盖三个成本费率：

```
effectiveConfig = costOverride !== null
  ? { ...priceConfig, ...costOverride }     ← 使用覆盖值
  : priceConfig                              ← 使用全局默认值
```

覆盖的费率：
- `costAccessoryPrice` — 成本配件单价
- `costCuttingFee` — 成本切工费率
- `costTaxRate` — 成本税率

**重要约束**：
- 覆盖只影响当前报价单，不写回全局配置
- 历史记录保存的是 effectiveConfig 完整快照
- 载入历史记录时自动检测 cost* 差异，恢复覆盖

## 七、完整计算示例

### 假设条件

```
成本库记录: G3406 哑黑 → materialCost = 5.10 元/米, weightPerMeter = 0.85 kg/m
全局费率: materialPrice = 12 元/米, mode = BATCH
  quoteAccessoryPrice = 3.5 元/套, quoteCuttingFee = 5 元/个, quoteTaxRate = 0.13
  costAccessoryPrice = 3.0 元/套, costCuttingFee = 4 元/个, costTaxRate = 0.10
  defaultWeightPerMeter = 0.85 kg/m
输入: G3406 哑黑, 外径, 50×70cm, 数量 10
```

### 计算过程

```
边长:
  宽边 = 50/100 + 0.015 = 0.515m
  高边 = 70/100 + 0.015 = 0.715m

待切池: 10 个框 × 4 条边 = 40 条边
  宽边 20 条 × 0.515m = 10.300m
  高边 20 条 × 0.715m = 14.300m
  总长 = 24.600m

排料: 24.600m ÷ 3.05m/支 ≈ 8.06 → 9 支
  (实际需要 9 支 3.15m 整料)
```

```
查价: G3406 哑黑 → 精确匹配 costDatabase → costMaterial = 5.10 元/米

批量单计算:
  avgMeters = 9 × 3.15 / 10 = 2.835m/框

报价单价:
  unitPrice = [2.835 × 12 + 3.5 + 5] × (1 + 0.13)
            = [34.02 + 3.5 + 5] × 1.13
            = 42.52 × 1.13
            = 48.05 元/框

报价总额 = 48.05 × 10 = 480.50 元

报价轨道成本:
  materialCost = 9 × 3.15 × 5.10 = 144.59 元
  accessoryCost = 10 × 3.5 = 35.00 元
  cuttingCost = 10 × 5 = 50.00 元
  subTotal = 229.59 元
  taxCost = 229.59 × 0.13 = 29.85 元
  totalCost = 259.44 元

成本轨道成本:
  costAccessoryCost = 10 × 3.0 = 30.00 元
  costCuttingCost = 10 × 4 = 40.00 元
  subTotalCost = 144.59 + 30.00 + 40.00 = 214.59 元
  costTaxCost = 214.59 × 0.10 = 21.46 元
  costGrandTotal = 236.05 元

利润:
  profit = 480.50 - 236.05 = 244.45 元
  profitMargin = 244.45 / 480.50 × 100 = 50.9%
```

## 九、关键边界情况

| 边界情况 | 处理方式 |
|---------|---------|
| 成本库无对应型号颜色记录 | 四级查价回退到估算（materialPrice × 0.6） |
| 排料算法校验不一致 | 回退 FFD 算法，记录 warning 日志 |
| 零散单模式：材料单价显示 | 直接取 `costMaterial` 字段，不通过除法反推 |
| 单框成本费率覆盖 | effectiveConfig 模式，全局不污染 |
| 历史记录数据缺失 | 完整兜底策略（Array 检查、字段存在性验证） |
| 过长的边（> 3.05m） | 单独占一支料（实际业务中罕见） |
